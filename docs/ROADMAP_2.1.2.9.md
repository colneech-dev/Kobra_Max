# Kobra Max firmware and display: roadmap on Marlin 2.1.2.9

Written 2026-10-30 on branch `marlin-2.1.2.9`. Companion files: `docs/PLAN_2.1.2.9.md` (the immediate fix list) and
`docs/UPGRADE_2.1.2.9.md` (what the port changed). Status words: **ported** = in the port already, **missing** = needs
porting, **new** = not in either firmware yet.

---

## 0. What was reviewed, and how far the review goes

| Source | How it was used |
|---|---|
| Anycubic's own source (`github.com/ANYCUBIC-3D/Kobra_Max`, "Kobra Max firmware V2.8.7", a Marlin `bugfix-2.0.x` snapshot) | The vendor baseline. Every line in its core files that appears in **no** Marlin 2.0.6.1 to 2.0.9.11 release was listed (83 files); comments, whitespace and pure version noise were then removed by reading. |
| `kobra-max-hc32` (our working firmware) vs Anycubic's source | 34 core files differ: our HC32 work, wabbitguy's MEL mods, and our fixes. Each one was read. |
| `kobra-max-hc32` vs `marlin-2.1.2.9` | Line diffs of the DGUS library, HC32 HAL, pins and display glue; effective `#define` comparison of both configuration files; every `ExtUI::on*` call site in both cores. |
| Marlin release notes 2.0.9 to 2.1.2.9 | Every "New Features", "Improvements" and "Issues Fixed" entry, filtered for this printer (HC32F460, TMC2209 UART, strain-gauge nozzle probe, bilinear mesh, SD-card EEPROM, ExtUI display). |
| An independent read-only review of the port | Findings merged below. |

**Limits.** 2.0.8 to 2.1.2.9 changes tens of thousands of lines. I did not read every line of upstream Marlin. I read
every line that the Kobra Max customizations touch, plus every release-note entry, plus the code paths behind the
entries that matter here (power loss, probe, homing, temperature, runout, settings, pause, ExtUI). Behaviour in upstream
code that the Kobra Max does not use (other kinematics, other displays, other HALs) was not reviewed.

## 3. Part B: Marlin 2.0.8 to 2.1.2.9, what matters here

### B1. Behaviour changes that must be handled (all on the fix list)

| Change | Effect on the Kobra Max | Action |
|---|---|---|
| EEPROM layout `V82` -> `V88` | First boot discards `eeprom.dat`: mesh, Z offset, PID, display language/sound | Procedure: `M503` before flashing; re-level and `M500` after. Optional: a one-off migration (Part D, "outside the box") |
| ExtUI hooks renamed (`onHomingDone`, `onPrintDone`, `onSettingsStored/Loaded`, `onLevelingStart/Done`, `onSetPowerLoss`) | Already adapted | none |
| Status texts: `MSG_REHEATDONE` "Reheat Done", purge "Purging..." | DGUS matches the old texts; after a heater-timeout reheat the print stays waiting | Update `dgus_tft_defs.h` |
| `PrintCounter::stop()` counts, `abort()` does not | Display aborts were counted | **ported** fix (b144c08) |
| Power-loss detection is a digital read | See A6 | Restore ADC detection |
| `DEFAULT_FEEDRATE_MM_M` 4000 (old firmware 2000 mm/min) | Moves sent without `F` before any `F` are twice as fast | Set `DEFAULT_FEEDRATE_MM_M 2000` in `Configuration_adv.h` to keep the old behaviour |
| Arc segments: `MIN_ARC_SEGMENT_MM 0.1`, `MAX_ARC_SEGMENT_MM 1.0` (old: 1 mm, 24 per circle) | Arc-heavy files plan many more segments | Keep, watch for stutter; raise `MIN_ARC_SEGMENT_MM` if seen |
| `PRINTCOUNTER_SAVE_INTERVAL 60` | Stats written to `eeprom.dat` every hour of printing | Keep |
| `POWER_LOSS_ZRAISE` default 2 | See A9 | Set 0 |
| Renames (`DEFAULT_KP`, `FAN0_PIN`, `ONBOARD_SDIO`, `DISABLE_IDLE_*`, `*_FEEDRATE_*`) | Done | none |

* Linear Advance + TMC timing fixes (2.1.1), "Fix, improve Linear Advance".
* `G2`/`G3` arc stutter and junction-deviation speed fix (2.1.1); arc optimisation.
* Axis homing fix (2.1.1); planner optimisations (2.1.1, 2.1.2).
* "Fix leveling XY move feedrate on ExtUI displays" (2.1.2.2): directly affects our G29 from the display.
* "Mount media early for POWER_LOSS_RECOVERY" (2.1.2.4); improved EEPROM validation (2.1.2.1).
* PID autotune cleanup and the endless `M303 C<3` fix (2.1.2.8): our Thermal Tuning page runs `M303 C8`.

* Park the nozzle on a "loud kill" (2.0.9.3): with `NOZZLE_PARK_FEATURE` (on) a thermal kill moves the nozzle off the print.

## 5. Part D: display plan

### D1. Constraints that shape every screen

* **Picture IDs.** Each page is a picture ID. 36 IDs in 1-217 are free outside the boot range 50-114:
  12, 14, 24, 28, 31, 46, 48, 116, 118-120, 126, 132, 134, 144, 148, 151, 155-169, 172, 174, 208, 210.
  IDs 252-255 are free too (stale pictures deleted). Pressed-button pictures use 35-49 and 218-251, all taken.
* **CHS/ENG mirrors.** Most screens exist twice (1-34 and 121-154) though only English is used. Making every page
  single-language (as the keyboard and Terminal already are) frees about 30 IDs and halves the art to maintain. This is the
  biggest single enabler for new screens (see D4).
* **Flash slots.** `16_68_.icl` sits in slots 16-28, with `29_ICO`, `30_Font`, `33_SPIN`, `34_SEL` after it. Each new
  picture costs ~12 KB in the library; dozens fit, but if the library outgrows slot 28 the later files must move
  (`build_release.py` already assigns slots; the rule "never overlap" is in `docs/DISPLAY_NOTES.md` 1.4).
* **Proven controls** only, unless a test is planned: return-key buttons, text (centred; pad the end to left-align),
  integer data variables, Basic Graphics fills (progress bars), Animation Icon (spinners). Untested but available:
  Real-Time Curves (7.21), QR Code (7.25), Text Scroll (7.16), sliders (6.10), Icon Rotation (7.7), Brightness (7.26).
* **Rules from experience:** never `ChangePageOfTFT` from Startup/ParamInit, never page 50; text fields are blank after
  a press or page redraw, so every value is re-sent periodically; one `injectCommands_P` pointer; no `printf("%f")`.

## 6. Part E: outside the box

1. **One-off settings migration.** Read the old V82 `eeprom.dat` layout (known: same file, old offsets) at first boot
   and carry the mesh, Z offset, PID and display settings over, instead of losing them. Saves a re-level after flashing.
2. **Auto Z offset from the strain gauge.** The nozzle is the probe, so the remaining offset is only the gauge's trigger
   deflection. A routine that probes a known reference (or measures trigger force consistency) could set it without
   paper; this is what Anycubic's stock `M1024` page (115, hidden) promised. Research item.
3. **First-layer monitor.** During the first layer the Z-offset page is one tap away; remember the last babystep as the
   new offset only after the user confirms ("keep this offset?").
4. **Power monitor on screen.** PC2 already measures the 24 V rail (`POWER_MONITOR_VOLTAGE`); show it on the About /
   Diagnostics page and warn on brown-outs (it is also the input for A6).
5. **MCU temperature.** The HAL reads the HC32 on-chip sensor (`OnChipTemperature`); show it and use it for the board
   fan (`CONTROLLER_FAN_MIN_BOARD_TEMP`) instead of running the fan whenever the steppers are on.
6. **QR codes on fault pages** (DGUS control 7.25): each fault page links to a short fix guide. Untested control.
7. **Temperature graph** (Real-Time Curves 7.21) on the Temperature page: shows overshoot and PID behaviour.
8. **Print history** on SD: append file name, time, result (done / aborted / power loss) to `history.csv`; a page
   lists the last 10 and reprints one.
9. **Host features:** `M73` from slicers, `HOST_PROMPT_SUPPORT` already on; Terminal reply capture already works for
   USB hosts too.
10. **Continuous integration.** A GitHub Actions workflow that builds both branches' firmware, generates the display
    set and runs `cross_check_display.py` on every push, attaching the release zip. Catches the "stale picture" and
    build-break classes of bug before they reach the printer.
11. **A DGUS protocol logger** in debug builds: record every frame to the SD card for a session, so display problems
    can be replayed offline instead of diagnosed from photos.
12. **A display simulator** (Python, from the same generators and the touch/show files): click through pages on the PC
    and see which key codes and VPs fire. Halves hardware test cycles for screen work.
13. **Alternative path, for completeness:** community Klipper work exists for the HC32F460 and the Kobra Max (support status unverified). It would
    lose this DGUS UI unless the display is driven from the host. Not recommended while the Marlin port is on track,
    but it is the escape hatch if 2.1.x on HC32 hits a wall.

## 7. Part F: test and release process

**Gate 1 (base port, after P0):** the first-flash checklist from the review:
`M503` saved; boot banner; `M105`; `M119` (endstops, probe, sensor); probe tare; separate X/Y/Z homing and one forced
homing failure; heat to 60 C both heaters; `M500`/`M501` round trip and power cycle; `G29`, save, power cycle, mesh and
Z offset on the display; first print raised, abort from the display and check the statistics; M600 and runout flow
including heater-timeout reheat; colour change across two prints; power-loss test only with `M413 O` and a dry run.

**Gate 2 (features):** each P1 feature on its own release, one change per flash, with a test print and a note in
`docs/`.

**Release hygiene:** commit before building (build id), `release_vNN` per flash, cross-check clean, never push the port
branch until Gate 1 passes (or push as a clearly named WIP branch if a backup is wanted).

## 9. Decisions needed

1. Power-loss: restore ADC detection (recommended) or disable detection.
2. Resume: home Z (recommended) or trust saved Z; `POWER_LOSS_ZRAISE` 0 (recommended) or 2.
3. Keep the old 5 mm/s minimum feedrate (A14)? Recommended: no (upstream behaviour), unless slow purges misbehave.
4. Order of phases 2-8; whether single-language pages (phase 2) go ahead.
5. MPC vs PID, JD vs classic jerk, StealthChop (pending MD decisions from earlier sessions).
